# Spec Delta

## MODIFIED Requirements

### Requirement: 辅助弹窗统一结构

系统 SHALL 让「使用帮助」「检查更新」「变量说明」弹窗共用同一标题栏（标题 + 关闭）、内容区与页脚操作区；使用帮助保留快速开始、功能说明、使用技巧、常见问题、二维码反馈五个分段，检查更新的页脚 SHALL 只保留「忽略此版本」与「稍后」两个操作，SHALL NOT 再提供「立即更新」按钮，打开更新页面 SHALL 只由内容区的 Release 地址承担。

#### Scenario: 使用帮助分段完整
- **WHEN** 用户从状态栏右端的「使用帮助」入口打开帮助弹窗
- **THEN** 五个分段均可切换查看，二维码反馈入口可见，弹窗不遮挡主窗口的状态栏

#### Scenario: 忽略版本
- **WHEN** 用户在新版本提示中选择「忽略此版本」
- **THEN** 该版本写入现有 `ignored_version` 字段，后续启动不再提示该版本

#### Scenario: 检查更新弹窗操作区
- **WHEN** 用户打开「检查更新」弹窗并查看页脚
- **THEN** 页脚只有「忽略此版本」与「稍后」两个操作，不存在「立即更新」按钮，内容区的 Release 地址与公众号二维码仍然可见

## ADDED Requirements

### Requirement: 检查更新弹窗先呈现内容再异步填充结果

「检查更新」弹窗 SHALL 在用户点击状态栏版本号后立即显示，内容区第一行 SHALL 展示当前版本号，第二行 SHALL 承载最新版本信息：拉取中显示「正在检查最新版本中…」，失败显示「检查最新版本失败」，成功显示最新版本号与可点击的 Release 地址。

#### Scenario: 弹窗先于网络请求出现
- **WHEN** 用户点击状态栏版本号
- **THEN** 弹窗在发起网络请求之前就已显示，第一行为当前版本号，第二行为「正在检查最新版本中…」

#### Scenario: 拉取成功
- **WHEN** 版本清单拉取成功且存在更高版本
- **THEN** 第二行显示最新版本号与该版本对应的 GitHub Release 地址，地址以超链接呈现，点击后用默认浏览器打开该页面

#### Scenario: 拉取失败
- **WHEN** 版本清单请求超时、网络不可达或返回内容无法解析
- **THEN** 第二行显示「检查最新版本失败」，弹窗保持可用，用户可关闭弹窗或扫描二维码，且不出现额外的错误消息框

#### Scenario: 已是最新版本
- **WHEN** 版本清单拉取成功但远程版本不高于本地版本
- **THEN** 第二行说明当前已是最新版本，不展示指向更高版本的下载入口

### Requirement: 检查更新弹窗展示公众号二维码兜底

检查更新弹窗 SHALL 在内容区展示项目固定的公众号二维码，作为无法访问 GitHub 时的备选方案；该二维码 SHALL 不随应用版本变化，SHALL 读取随应用打包的本地资源，SHALL NOT 依赖网络下载；资源缺失时 SHALL 降级为文字提示而不报错。

#### Scenario: 二维码离线可用
- **WHEN** 用户所在网络无法访问 GitHub 或任何外网资源
- **THEN** 公众号二维码仍正常显示，用户可扫码获取更新方式，弹窗不出现加载失败提示

#### Scenario: 二维码为固定资源
- **WHEN** 用户对比不同应用版本的检查更新弹窗
- **THEN** 展示的是同一张公众号二维码，不随版本号或 Release 内容变化

#### Scenario: 二维码资源缺失
- **WHEN** 打包产物中缺少二维码图片
- **THEN** 弹窗在该位置显示获取更新方式的文字提示，不弹出错误框、不影响其余内容
