# 票易合 v2 · 字体与界面对应关系（字体对齐基线）

> 权威来源：设计稿 `req/ui/00`–`04`、设计稿 `.op` 源文件（`fontFamily` 节点）。
> 实现唯一来源：`code/ui/tokens.py`。本文件是字体映射与冲突清单的说明文档，不参与运行时。

---

## 1. 设计稿字体清单

| 用途 | 字体族 | 随程序打包字体 | 许可 |
| --- | --- | --- | --- |
| 中文（设计稿） | Noto Sans SC（可变字体） | `code/res/fonts/NotoSansSC-VF.ttf` | SIL OFL 1.1 |
| 中文（桌面首选，实际渲染） | Microsoft YaHei UI（系统字体） | 无（随 Windows 提供） | 系统许可 |
| 数字 | Inter（可变字体）+ OpenType `tnum` | `code/res/fonts/Inter-VF.ttf` | SIL OFL 1.1 |

- 设计稿 `.op` 源文件中，所有数字节点的 `fontFamily` 均为 **Inter**；中文节点为 **Noto Sans SC**。
- **桌面实现有意改用微软雅黑 UI 渲染中文**：Noto Sans SC 由自动工具生成，不含 TrueType
  hinting 指令，Windows 96 DPI（1x）下 12–13px 的横画无法吸附像素格而发虚；雅黑是微软
  逐字形调过指令的屏幕字体，同字号下边缘像素占比 42.8% vs 47.9%。字形代价是雅黑更方正、
  x-height 略高。详见 §6.6。Noto 仍随包分发并留在回退链中，macOS / Linux 自动用回它。
- `req/ui/00` 说明页「等宽数字样例」上出现的 `Geist Mono` 是该行标签的示意文字，**不是设计稿字体**。
  Geist Mono / JetBrains Mono / Consolas 在目标机不存在会静默回退 Arial（比例数字、字形不符），
  并让 Qt 额外做一次字体别名扫描拖慢启动，已全部从实现字体栈移除。
- 数字用 `tnum`（tabular numerals）得到等宽数字，再右对齐；**不切换到等宽字体族**。

### 字体栈（`tokens.py`）

```text
FONT_CN_STACK   = "Microsoft YaHei UI","Microsoft YaHei","Noto Sans SC","Source Han Sans SC","Source Han Sans CN","PingFang SC","SimHei","DengXian",sans-serif
FONT_MONO_STACK = "Inter","Microsoft YaHei UI","Microsoft YaHei","Noto Sans SC",monospace
```

`FONT_MONO_STACK` 中 Inter 之后是中文回退链，使**中文混排文本**中的中文与界面其余部分同族，
数字仍走 Inter。

### 启动顺序（不可变）

```text
QApplication 创建
  → apply_application_style()
      → register_bundled_fonts()      # 注册 Inter-VF / NotoSansSC-VF
      → app.setStyleSheet(build_stylesheet())
      → app.setFont(Microsoft YaHei UI, 14px, Weight.Normal 400)
  → 构建窗口 / 对话框
      → clear_inline_styles(root)
      → apply_numeric_text_fonts(root)   # 数字位 setFont(Inter + tnum)
```

顺序错了 QSS 里的字体名会回退到系统里另一种字形。应用级默认字体用 `setPixelSize(FONT_SIZE["base"])`
（当前 14px），**不写 `QFont(family, 9)`**（=12px，偏小发虚）。深色/浅色主题只换色值，字体族、字号、字重完全相同。

## 2. 字重 / 字号档位常量（`tokens.py`）

设计稿 `req/ui/00`「05 / 字体与数字」标注：`Regular 13 / Medium 14 / SemiBold 16 / Bold 20`，
行高 22、字距 0。Qt/QSS 使用 100–900 数值字重，映射集中定义在 `FONT_WEIGHT` / `FONT_SIZE`：

| 设计稿命名 | 数值字重 | 常量键 | 界面用途 |
| --- | --- | --- | --- |
| Regular | 400 | `FONT_WEIGHT["regular"]` | 正文、表头常规、chip |
| Medium | 500 | `FONT_WEIGHT["medium"]` | 次级强调 |
| SemiBold | 600 | `FONT_WEIGHT["semibold"]` | 选中态、强调标签、执行按钮 |
| Bold | 700 | `FONT_WEIGHT["bold"]` | 标题、主按钮、金额合计 |

| 字号键 | px | 界面用途 |
| --- | --- | --- |
| `micro` | 10 | 进度条百分比 |
| `caption` | 12 | 次级/弱化文字、表头、状态栏、版本号 |
| `body` | 12 | 参数值、表格数据、芯片 |
| `base` | 14 | 正文基线（`FONT_BODY_PIXEL_SIZE`）。设计稿 13px，因 Windows 1x 栅格余量抬一档，见 §6.5 |
| `subhead` | 14 | 卡片标题、主按钮（与 `base` 同字号，靠 Bold + 主色分级） |
| `title` | 15 | 品牌名、合计金额 |
| `heading` | 16 | 台账标题、弹窗小节标题 |
| `dialog` | 18 | 弹窗主标题 |

> **Bold 20px（`DESIGN_DISPLAY_SIZE`）：【设计稿展示用，界面不消费】**
> 仅用于 `req/ui/00` 说明页大标题「票易合 · 财务级 UI 重构设计说明」。
> 界面中没有对应控件，因此**未加入 `FONT_SIZE`、未生成任何 20px QSS 规则**，请勿据此新增。

QSS 中所有 `font-size` / `font-weight` 均引用 `{S[...]}` / `{W[...]}` 常量，源码中无魔法数字。

### 必须保持中文栈的混排内容

- `ruleInput`（重命名规则含中文占位符）、`fieldChip` / `fieldChipExtra`（中文字段名）、
  帮助说明正文、二维码提示、按钮文字、中文下拉（`modeCombo` / `orderCombo`）。
- 这些控件**不得**使用数字字体，否则中文会被回退到非设计稿字体。

### 三层数字字体策略（Qt 技术约束下的实现）

1. **表格数值列**：`QTableWidgetItem.setFont(numeric_font(px))` — item 的 FontRole 优先于 QSS，
   `tnum` 生效，小数点按列对齐。
2. **纯数字/金额标签与输入控件**：`QWidget.setFont(numeric_font(px))`，且对应 QSS 规则
   **不声明 `font-family`**（否则 Qt QSS 会覆盖 `setFont()`，导致 `tnum` 丢失）。
3. **中文 + 数字混排的次级文本**：`apply_numeric_text_fonts()` 用带中文回退链的
   `numeric_font()` 统一设置；中文经 `setFamilies` 回退到中文栈首位（Microsoft YaHei UI），数字走 Inter + tnum。

> Qt QSS **不支持** OpenType `font-feature-settings` / `tnum`，也不支持按字符切换字体。
> 因此凡需 `tnum` 的控件一律走 `setFont()`；QSS 只负责字号、颜色与几何，不声明字体族。

## 4. QSS 与 `setFont()` 冲突清单（本次已全部消除）

| # | 冲突点 | 原状态 | 处置 |
| --- | --- | --- | --- |
| 1 | 表头字重 | `QHeaderView::section { font-weight: 500 }` 与 `file_list.py::_apply_header_colors()` 的 `setBold()` 同时指定 | QSS 移除表头 `font-size`/`font-weight`；统一由 `tokens.header_font(bold)` 单一来源生成（12px / 中文栈首位 Microsoft YaHei UI / Regular，仅金额列 Bold + 主色） |
| 2 | 通用 `QLabel` 字体 | `QLabel { font-family; font-size: 13px }` 会覆盖所有数字位的 `setFont()`，`tnum` 失效 | 通用 `QLabel`、`QMainWindow`/`QDialog` 规则不再声明 `font-*`；默认字体由 `app.setFont()` 唯一提供，各 `objectName` 规则显式给字号 |
| 3 | 通用表单字体 | `QLineEdit, QComboBox, QSpinBox` 的 `font-family` 覆盖数字输入框的 `setFont()` | 通用表单规则移除 `font-family`；数字输入位纳入 `NUMERIC_INPUT_OBJECTS` 由 `numeric_font()` 覆盖；`ruleInput` 显式保留中文栈 |
| 4 | 纯数字标签 | `versionLabel` / `monoLabel` / `ledgerTotalLabel` / `exampleValue` 规则内声明 `font-family`/`font-size`/`font-weight`，与 `setFont()` 重复 | 这些规则只保留颜色与几何，字体全部由 `numeric_font()` 单一来源提供 |
| 5 | 混排数字文本 | 状态栏/页码/chip 走中文栈比例数字，与设计稿 Inter 字形不符 | 加入 `NUMERIC_TEXT_OBJECTS`，由 `apply_numeric_text_fonts()` 集中设置 Inter + tnum |
| 6 | 逐控件内联样式 | `main_frame.py` 帮助正文、二维码标签、分隔线等 9 处 `setStyleSheet` 写 `font-size` | 全部改为 `setObjectName()` + QSS 规则（`helpText` / `qrcodeHint` / `qrcodePlaceholder` / `hSeparator`）；旧版遗留方法中的同类内联声明与注释一并清理 |

**非冲突的分层覆盖（保留）**：`QTableWidget` 的 12px 中文栈是单元格默认值（供文件名/路径中文列使用），
6 个数值列与表头由 `setFont()` 覆盖 —— item 的 FontRole 优先于控件 QSS，属设计意图，实测 11px/12px 均生效。

## 6. Windows 1x 屏「字发虚」的根因与 P0/P1 修正

### 6.1 根因：打包字体不含 TrueType hinting 指令

直接解析字体表目录（`fpgm` / `prep` / `cvt ` 三张表即网格拟合指令）：

| 字体 | fpgm | prep | cvt | 其余 |
| --- | --- | --- | --- | --- |
| `NotoSansSC-VF.ttf`（打包） | ✗ | ✗ | ✗ | 仅 `gasp` + `glyf` |
| `Inter-VF.ttf`（打包） | ✗ | ✓ | ✗ | 仅 `gasp` + `glyf` |
| `segoeui.ttf`（系统） | ✓ | ✓ | ✓ | + `hdmx` / `VDMX` / `LTSH` |

没有指令，13px 下的横画无法吸附到像素格，只能摊在两行像素上各 50% 灰。设计稿在
macOS 2x 屏上（13px 等效 26 物理像素）笔画有足够像素铺满，所以看不出问题；迁到
Windows 96 DPI 的 1x 屏后就没有余量了。

### 6.2 量化对比（9 段中文取平均，白底，20% 灰字）

「半透明边缘像素占比」越低越锐利；「每实心像素摊到的墨迹」越接近 1 越结实。

| 字体 | 字号 | 半透明边缘占比 | 实心笔画 | 每实心像素摊墨迹 |
| --- | --- | --- | --- | --- |
| Noto Sans SC | 11px | 48.6% | 118 | 3.45 |
| Noto Sans SC | 13px | 48.6% | 163 | 3.11 |
| Noto Sans SC | 14px | 46.9% | 190 | 2.95 |
| Microsoft YaHei UI | 13px | 43.2% | 179 | 3.00 |

已排除的三条猜测：`AppliedDPI=96`（非缩放问题）；`PreferFullHinting` 对 Noto
完全无效（三档设置下数值逐像素相同，因字体内无指令可执行）；切
`fontengine=gdi` 反而更糊（边缘占比 48.6% → 68.2%，实心笔画 163 → 92）。

### 6.3 P0：`text_muted` 对比度不足

`#8A97A8` 在白底只有 2.97:1（页面底色 `#F4F6F9` 上 2.74:1），低于 WCAG 小字
4.5:1；该色承担状态栏、单位后缀、路径列等小字，叠加后视觉发虚。

| 令牌 | 原值 / 对比度 | 新值 / 对比度 |
| --- | --- | --- |
| `text_muted`（浅） | `#8A97A8` 2.97:1 | `#667085` 4.97:1 |
| `text_muted`（深） | `#74869A` 4.18:1 | `#8798AC` 5.29:1 |

层级保持：`text_secondary` 浅色 5.46:1 / 深色 7.16:1，仍高一档。

### 6.4 P1：`caption` 11 → 12px

实心笔画 118 → 140（+19%）。表头 12px 同时与设计稿实测值一致（4b-9），此前
代码用 11px 才是偏差。`caption` 与 `body` 因此同为 12px，层级改由颜色与字重区分。

连带修正：`versionLabel` 内容区原 `min-height/max-height: 14px` 装不下 12px 字
（字高 15px，实测 1px 裁切），改为 `padding: 2px 8px; height: 16px`，总高仍为
`16 + 4 + 2 = 22px`，状态栏四项同高的既有约束不变。

### 6.5 P2：`base` 13 → 14px

只抬正文基线一档，其余档位不动（`subhead` 仍为设计稿的 14，故与 `base` 同字号，层级由
700 字重与主色承担；`caption` / `body` 保持 12）。

实测：对 5 个真实按钮的文字区取色统计，按主色剔除控件底色后只计墨迹像素。

| 按钮 | 实心笔画 13 → 14 | 每实心像素摊墨迹 13 → 14 |
| --- | --- | --- |
| 添加文件 | 70 → 95（+36%） | 3.90 → 3.45 |
| 删除选中 | 98 → 116（+18%） | 2.90 → 2.91 |
| 上移 | 25 → 40（+60%） | 4.96 → 3.62 |
| 批量重命名 | 174 → 206（+18%） | 2.47 → 2.43 |
| 导出列表 | 111 → 134（+21%） | 2.61 → 2.52 |

影响面：`base` 只被按钮、输入框、`QTextEdit`、复选框与票种导航按钮消费。表格数据、
参数标签与状态栏用的是已抬到 12px 的 `caption` / `body`，不受这一档影响——这也是
P1 之后界面里唯一还剩的 13px 面。

几何：五段式外壳靠 `QSplitter` 与拉伸项吸收约 7% 的文字增宽，无需重排。

- 主窗口 `minimumSizeHint` 仍为 1295×702，低于代码里的 `setMinimumSize(1400, 800)`，不会反向撑窗；
- 操作条最小需求 857px，1440 宽下实际 976px，无溢出；
- 固定尺寸控件仍有余量：`打开文件` 86×34（文字余量 4px）、`浏览` 62×34（8px）、
  `合并 PDF` 152×40、重命名弹窗四个按钮 76 / 76 / 88 / 132；
- 72 个文本控件几何逐一比对：0 处变化；`check_clip.py` 0 处裁切。

### 6.6 P2-B：中文栈首位换成 Microsoft YaHei UI

§6.5 用抬字号掩盖 Noto 的 hinting 缺失；本条从字体本身解决，代价是字形与设计稿不同。

| 项 | Noto Sans SC | Microsoft YaHei UI |
| --- | --- | --- |
| `fpgm` / `prep` / `cvt` hinting 表 | ✗ ✗ ✗ | ✓ ✓ ✓ |
| 12px 半透明边缘像素占比 | 49.7% | **48.1%** |
| 13px 同上 | 48.6% | **43.2%** |
| 14px 同上 | 47.2% | **45.9%** |
| 实心笔画 / 每实心像素摊墨迹（13px） | 179 / 3.11 | 179 / **3.00** |

真实控件测量（windows 平台同进程 A/B，替换前后）：

| 位置 | 半透明边缘占比 | 实心笔画 |
| --- | --- | --- |
| 文件名单元格（12px） | 47.9% → **42.8%** | 520 → **590（+13%）** |
| 「添加文件」按钮 | 68.4% → **60.1%** | 80 → 121 |
| 「删除选中」按钮 | 56.2% → **50.0%** | 122 → 138 |
| 「导出列表」按钮 | 58.5% → **55.2%** | 123 → 134 |
| 「合并 PDF」按钮 | 44.6% → **40.3%** | 19 → 62 |

字重缺口：雅黑 UI 只有 `Regular / Light / Bold`，**没有 Medium(500) 与 SemiBold(600)**。
QSS 中 `font-weight: 600` 会落到 Bold，比设计稿略重；`FONT_WEIGHT["medium"]` 目前无消费点。

布局影响（windows 平台 A/B，75 个控件）：

- 汉字 advance width 与 Noto 完全一致（均 1em），中文布局零漂移；
- 仅中英混排字符串变宽，最大一处是「支持 PDF / PNG / JPG / OFD」+7px（+4.5%）；
- 7 处控件尺寸变化均为内容自适应收缩（如「添加文件」按钮 100→96、「实时预览：开」78→72），无溢出；
- 雅黑 14px 的行高（15px）比 Noto 14px（17px）低 2px，多行说明文字块自然变矮。

连带修正：裁切线两个数字框（`bareSpin`）宽度 60 → 64px、前缀空格 2 → 1。
雅黑下「左  0 mm」需 53px 而内容区只有 48px，末位 `m` 被削掉——Noto 时代已有 2~3px 隐性裁切，
只是字形窄而不明显。改动后内容区 52px，余量 2px。

### 6.7 验收

- 布局：72 个文本控件逐一比对改动前后几何，表头 34px、行高 38px 均未变；
  `check_clip.py`（内容区高度 vs 字高）从 1 处裁切降为 0。P2 抬 `base` 后仍为 0。
- 测试：`py -3.14 -m unittest discover` → 224 项 / 失败 0 / 错误 0 / 跳过 3。
